# 작업 노트 (한국어)

**이 폴더는 전시 사본이다.** 원본은 Obsidian 볼트 `Projects/테트리스 T-패리티/` 의 노트이고,
동기화는 볼트 → docs/ko 한 방향이다. 여기를 먼저 고치고 볼트를 안 고치면 방향이 뒤집힌다.
결정 기록과 검산 대장도 볼트에 있다 (`Decisions.md`, `검산 대장.md`).

README.md 는 이 노트들을 영어로 압축한 것이다.

- `classification-ko.md`    조각 부분집합 분류. 보조정리 0·M, 정리 1~5, 정정 기록
- `model-ko.md`             모델의 형식적 정의 (L1)(L2)(L3) 와 모델 의존도 분석
- `literature-ko.md`        선행연구 조사와 신규성 판정
- `t-parity-ko.md`          동적 T-패리티 항등식과 전수 검증
- `seven-bag-ko.md`         7-bag 제약 하의 최소 조각 수 (폭 4..16)
- `seven-bag-order-ko.md`   7-bag 순서 제약 (bag1 x bag2 고정)
- `decisions-ko.md`         결정·오류 수정 기록 (볼트 Decisions.md 사본)
- `ledger-ko.md`            검산 대장 — 모든 숫자의 재현 명령 (볼트 사본)

## 검산 규칙

이 연구에서 나온 오류는 전부 수학이 아니라 **도구 배관**이었다.
같은 함정에 다시 빠지지 않도록 기록한다.

- 보드 비트폭 확인. hcap x w 가 64 를 넘으면 __int128 필수
- 셸 루프에서 timeout 의 빈 출력을 반드시 검출. 빈 출력은 "불가능" 이 아니다
- 탐색기 인자(패리티·마스크)를 조각 집합마다 재확인
- 좌우 대칭 정규화는 거울에 닫힌 조각 집합에만 적용
  (L 의 거울상은 J 이므로 L 단독 탐색에 쓰면 해를 놓친다)
- 수상한 숫자는 끝까지 추적. 상태 수 2.6% 불일치 하나가 결함 두 개를 드러냈다
- 한계값과의 일치를 확인할 것 (INCONCLUSIVE 46,976,203 = 2^26 x 0.7 이었다)
- 코드 검산과 별개로 **서술도 검산**. 정리 1(b) 는 계산이 맞고 글이 틀렸다
- **CAP / INCONCLUSIVE / TIMEOUT 은 "가능" 도 "불가능" 도 아니다.** 상한을 올려
  재실행해 확정하기 전에는 결론으로 쓰지 말 것 (b2all.out 의 CAP 4 건을 한 번 오독했다)
- Makefile·셸에서 `프로그램 | head` 는 SIGPIPE 로 조용히 깨진다. 파이썬은
  BrokenPipeError 로 죽는데 make 는 exit 0 을 돌려준다. `sed -n` 을 쓸 것
- 개수 주장은 **합인지 최대인지** 명시할 것 (7,141 은 H=18 단독이고 합계가 아니었다)
