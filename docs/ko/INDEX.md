# 작업 노트 (한국어)

**이 폴더는 전시 사본이다.** 원본은 Obsidian 볼트 `Projects/테트리스 T-패리티/` 의 노트이고,
동기화는 볼트 → docs/ko 한 방향이다. 여기를 먼저 고치고 볼트를 안 고치면 방향이 뒤집힌다.
결정 기록과 검산 대장도 볼트에 있다 (`Decisions.md`, `검산 대장.md`).

README.md 는 이 노트들을 영어로 압축한 것이다.

- `classification-ko.md`    조각 부분집합 분류. 보조정리 0·M, 정리 1~5, 정정 기록
- `model-ko.md`             모델의 형식적 정의 (L1)(L2)(L3) 와 모델 의존도 분석
- `literature-ko.md`        선행연구 조사와 신규성 판정
- `t-parity-ko.md`          동적 T-패리티 항등식과 전수 검증
- `seven-bag-ko.md`         7-bag 제약 하의 최소 조각 수 (폭 4..16)
- `seven-bag-order-ko.md`   7-bag 순서 제약 (bag1 x bag2 고정)
- `t-widths-ko.md`          정리 3(b) T 단독 임의 폭 — 유도·검산·인터뷰 기록
- `decisions-ko.md`         결정·오류 수정 기록 (볼트 Decisions.md 사본)
- `ledger-ko.md`            검산 대장 — 모든 숫자의 재현 명령 (볼트 사본)

## 검산 규칙

이 연구에서 나온 오류는 전부 수학이 아니라 **도구 배관**이었다.
같은 함정에 다시 빠지지 않도록 기록한다.

- 보드 비트폭 확인. hcap x w 가 64 를 넘으면 __int128 필수.
  **메모 키가 보드를 왼쪽으로 밀면 그 여유 비트까지 빼고 계산할 것.**
  pc3 는 키가 (board << 8) | meta 라서 실제 한계가 hcap x w <= 120 이다.
  넘으면 서로 다른 상태가 같은 키를 갖고 거짓 "NO" 가 나온다 (2026-09-15 에 w=18,19,20 에서 발생)
- 셸 루프에서 timeout 의 빈 출력을 반드시 검출. 빈 출력은 "불가능" 이 아니다
- 탐색기 인자(패리티·마스크)를 조각 집합마다 재확인
- 좌우 대칭 정규화는 거울에 닫힌 조각 집합에만 적용
  (L 의 거울상은 J 이므로 L 단독 탐색에 쓰면 해를 놓친다)
- 수상한 숫자는 끝까지 추적. 상태 수 2.6% 불일치 하나가 결함 두 개를 드러냈다
- 한계값과의 일치를 확인할 것 (INCONCLUSIVE 46,976,203 = 2^26 x 0.7 이었다)
- 코드 검산과 별개로 **서술도 검산**. 정리 1(b) 는 계산이 맞고 글이 틀렸다
- **CAP / INCONCLUSIVE / TIMEOUT 은 "가능" 도 "불가능" 도 아니다.** 상한을 올려
  재실행해 확정하기 전에는 결론으로 쓰지 말 것 (b2all.out 의 CAP 4 건을 한 번 오독했다)
- Makefile·셸에서 `프로그램 | head` 는 SIGPIPE 로 조용히 깨진다. 파이썬은
  BrokenPipeError 로 죽는데 make 는 exit 0 을 돌려준다. `sed -n` 을 쓸 것.
  `명령 | tee 파일 | head` 도 같은 이유로 **파일이 잘린다**
- 개수 주장은 **합인지 최대인지** 명시할 것 (7,141 은 H=18 단독이고 합계가 아니었다)
- **편향된 순서의 앞부분을 표본으로 읽지 말 것.** 정규형을 "궤도의 사전 최소" 로 잡았더니
  가장 작은 글자가 앞에 오는 류로 대표가 몰렸고, 그게 하필 쉬운 구간이었다 (2026-09-19).
  48 류의 "실패 0" 은 결과가 아니라 순서의 그림자였다. 정규형이 순서에 넣는 편향을 먼저 볼 것.
  알려진 답을 앞쪽에 대조군으로 두면 편향이 바로 드러난다
- **`timeout` 을 거는 파이썬은 `python3 -u` 로.** stdout 이 tty 가 아니면 블록 버퍼링이고
  SIGTERM 은 버퍼를 안 비운다. 시작 직후 찍힌 결론까지 통째로 사라진다 (2026-09-19).
  출력이 비었다고 "결론이 안 났다" 로 읽으면 안 된다
- **프로세스를 고를 때 "명령줄 전체" 를 매치하지 말 것 — 도구가 무엇이든.**
  그 프로세스를 띄운 셸의 명령줄에도 같은 문자열이 있어 **자기 자신을 죽인다**.
  네 번 당했다: `pkill -f` 두 번(09-18), `pgrep -f | kill`(09-19),
  `ps -eo args | grep | kill`(09-20). 마지막 건은 규칙이 `pkill -f`·`pgrep -f` 만
  금지한 탓에 **같은 짓을 다른 이름으로** 한 것이다. 함정은 도구가 아니라
  "명령줄 전체를 보는 것" 자체다.
  안전한 형태: `ps -C fix4 -o pid=` 나 `pkill -x fix4` (실행파일 **이름**만 본다).
  단 `ps -C` 도 함정이 있다 — bash 가 스크립트를 돌리면 자기 이름을 **스크립트 이름으로 바꾼다.**
  `/bin/bash ./scripts/bag1sweep.sh` 는 `ps -C bash` 로 안 잡히고 `ps -C bag1sweep.sh` 로 잡힌다.
  실행파일이 `bash` 라 이름으로 안 갈리면 **내 PID($$)와 부모를 먼저 제외**한 뒤 인자를 볼 것.
  병렬 작업은 부모(`ps -C xargs`)부터 죽여야 자식이 다시 안 태어난다
- **컨테이너에 남는 것은 커밋된 것이 아니라 푸시된 것이다.** 자동커밋 루프가
  `git push -q ... 2>/dev/null` 를 네 번 재시도하고 조용히 넘어가는 구조라
  커밋 29 개가 밤새 안 밀린 채로 쌓였다 (2026-09-20). 로그에는 `committed N` 만
  찍혀 정상으로 보였다. 긴 루프의 푸시는 성공 여부를 로그에 남기고,
  매 주기 `git log origin/BR..HEAD` 를 세어 밀린 것을 다시 밀 것
- **`A && B && C & D` 는 `&&` 사슬 전체를 백그라운드로 보낸다.** `&` 가 `&&` 보다
  결합이 약해서, `cd repo && S=/경로 && nohup 솔버1 > $S/a.out & ...` 로 쓰면
  `S` 가 백그라운드 서브셸에만 잡힌다. 부모 셸에서는 빈 문자열이라 두 번째 출력이
  `/b.out`(루트)로 갔다 (2026-09-21). 변수 할당은 사슬 밖 별도 줄에 둘 것.
  증상이 조용하다 — 파일이 없는 게 아니라 **엉뚱한 곳에 생긴다.**
  `ls -l /proc/<pid>/fd/1` 로 실제 stdout 을 확인할 수 있다
- **루프 하나를 고쳤다고 전부 재시작하지 말 것.** 돌던 작업의 `.partial` 을 버린다
  (840 중 705 까지 간 것을 날릴 뻔했다). 바꾼 루프만 교체하는 경로를 만들어 둘 것
